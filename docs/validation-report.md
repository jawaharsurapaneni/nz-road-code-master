## 3. Tests actually performed

### `node tools/validate.mjs` — PASS

Structural checks, run over all 275 questions:

- id format, uniqueness, and membership of the correct topic id block
- exactly four options, each with non-empty text and an explanation of at least 40 characters
- exactly one `correctOptionId`, which must resolve to an option that exists
- answer key matches the pre-generated balanced letter plan
- top-level explanation present and at least 60 characters
- topic, difficulty, ruleset, tags, source title, https source URL, source section and
  `lastVerified` date all present and well formed
- no placeholder text (TODO, TBD, FIXME, lorem ipsum, "placeholder")
- no duplicate ids, no duplicate question-plus-scenario prompts, no two equivalent options
  within a question, no generic "this is incorrect" explanations

Anti-pattern checks:

- option-length spread per question using `((longest − shortest) / mean) × 100`
- word-count spread and sentence-count mismatch per question
- correct option uniquely carrying a qualifier, a number, or standing alone against three
  absolute-word distractors
- bank-wide letter distribution, consecutive-run length and A-B-C-D cycle detection
- bank-wide correct-is-longest and correct-is-shortest percentages
- bank-wide correlation between absolute words and incorrectness

Shuffle integrity: 1000 seeded shuffles were performed, asserting after each that all four
options survive, that ids stay unique, and that the correct option's id, text and explanation
remain bound together.

### `node tools/check-contrast.mjs` — PASS (142 passed, 0 failed)

The interface follows the visual language of the airsup.ai lab pages
(https://www.airsup.ai/lab/skill), whose published stylesheet was read on 2026-10-14:
a warm paper palette (page `#f3f2ee`, card `#fbfaf7`, ink `#141414`, hairline `#e2e0da`), no
brand hue at all so ink itself is the accent, square corners throughout, large soft shadows,
and Instrument Serif set large and tight against Inter. The dark theme is a warm inversion of
the same palette rather than a cool charcoal, so both themes read as one product.

**Typography is the one part of that system deliberately not adopted.** The source site pairs
a large display serif with Inter, which suits a landing page and not a practice test. This app
sets one plain sans throughout at assessment-appropriate sizes: question text at 20-23px with
1.45 leading over a 58-character measure, body and options at 17px with 1.6 leading, and the
largest heading at 26-34px rather than 40-76px.

Inter is used because it was drawn for screen interfaces and keeps 1/l/I and 0/O visually
distinct, which matters when a question turns on a figure such as "100 metres" or on an option
letter. It is SIL Open Font License and base64-embedded as woff2 (47 KB raw), because the app
must work from `file://` with no network, and it falls back to a standard system sans. Bundle
tests assert the face is embedded as a `data:` URI, that no Google Fonts reference survives
the build, that no display serif is referenced, and that the fallback stack reaches a standard
sans.

This is standard assessment-legibility practice, not a reproduction of the official test. NZTA
does not publish the typeface used in its theory test and the app makes no claim to match it.

This gate resolves the custom properties out of `src/styles.css` and checks every
foreground/background pair the app renders **in both themes**, so it fails if a token is
changed to something unreadable in either. Colour values are not duplicated in the checker.

- 142 checks in total: 71 pairs across 2 themes
- text pairs are checked against the WCAG AA ratio of 4.5:1
- component pairs (button borders, focus rings, meters) are checked against 3:1
- lowest text contrast in the **light** theme: **4.56:1** (muted text on an alt panel)
- lowest text contrast in the **dark** theme: **5.51:1** (muted text on an alt panel)

It also asserts that the `prefers-color-scheme` fallback block — the palette that applies
before JavaScript runs — declares exactly the same values as the explicit dark theme, so a
dark-mode user cannot be shown a half-updated palette during startup.

**Departures from the published values**, all documented in the stylesheet and all for
accessibility. Three of the source palette's neutrals fall below WCAG AA, so they are kept for
decorative hairlines and darkened for text and controls:

| Token | As published | Measured on paper | Used here |
|---|---|---:|---|
| `--mute` | `#86847f` | 3.34:1 | `#6b6964` for text, 4.89:1 |
| `--faint` | `#c9c7c1` | 1.51:1 | `#89867e` for interactive borders, 3:1 |
| `--line` | `#e2e0da` | 1.18:1 | kept exactly, decorative only |

The source palette also has no success or error colours, so a deep forest green and an oxblood
red were introduced, desaturated to sit with warm neutrals.

**Defects this gate caught rather than the eye**: a danger-button hover label at 4.22:1, and an
active navigation pill rendering dark-on-dark at 1.18:1 in the dark theme. Both were fixed
before the build was accepted.

Note that this checks colour only. Font size, spacing, focus order and screen-reader output
are not verified here — see section 4.

### Interaction design — applied, and deliberately not applied

The information architecture follows the principles in *10 Best UX Websites of 2026*
(https://www.wandr.studio/blog/best-ux-websites). Most of the sites surveyed there are
commercial, so the principles were filtered rather than copied wholesale.

Applied, and covered by tests:

- a first-time visitor can answer five real questions in one click, with no setup screen
- the dashboard leads with one state-aware primary action rather than eleven equal tiles
- controls are grouped into *do this next*, *practise*, and *manage*
- an honest readiness signal replaces a wall of raw counts

**Not applied, on purpose.** Manufactured urgency, gamified incentives tied to spending,
sign-up funnel optimisation and artificial repeat-visit hooks are all recommended by that
article on the strength of commercial sites. In a road-safety study tool with no account and
no payment they would be user-hostile, and false urgency around safety content is actively
harmful. Spaced repetition already brings learners back for a real reason.

The readiness signal is deliberately strict: it says nothing until 35 questions have been
answered, and reaches its top band only with at least 60% coverage, 85% accuracy and a
completed full-length mock at or above the benchmark. Unit tests assert that coverage and
accuracy alone cannot reach that band, and that the signal always shows the figures behind
its verdict and never claims to predict the official result.

## 5. Known limitations and open questions

1. **No browser was run.** See section 4. The logic beneath and within the interface is
   covered by 86 unit tests and 36 render tests against a DOM shim, but nothing
   has been drawn by a real rendering engine or clicked by a real person.
2. **Rules change.** New Zealand road rules changed materially in 2024, 2025 and 2026, and
   change again on 25 January 2027. Every question records the page and the date it was
   checked; re-verify before relying on the bank after a rule change.
3. **The 2027 ruleset is partial.** It models only the graduated driver licensing changes
   confirmed on the official NZTA page: learner and restricted period lengths, the removal of
   the full licence practical test and eyesight check, the end of the advanced-course
   reduction, and demerit-driven extensions. It is not a complete future rulebook, and the
   detail could still be revised before commencement.
4. **The 32/35 benchmark** reflects the published learner theory test requirement as at
   2026-10-14. It is applied only to a completed full-length theory mock and never to
   the restricted practical preparation module.
5. **This is not an official test.** The questions are original, written against published
   rules. They are not actual examination questions, are not reproductions of any official or
   commercial question bank, and this app is not endorsed by NZTA Waka Kotahi or the AA.
6. **Multiple-choice cannot measure driving.** The restricted licence test is a practical
   on-road assessment. The restricted module rehearses decisions and observation habits only.
